# PROMPT OPENCODE — IMPROVEMENT UI/UX
# INVITE VIA EMAIL + DELETE ACCOUNT
# Desa Sehat Kenanga

Saya ingin melakukan PENAMBAHAN DAN PERBAIKAN UI/UX pada project yang sudah berjalan.

PENTING:
- Jangan membuat ulang project.
- Jangan mengganti tech stack.
- Jangan mengubah database schema yang sudah ada kecuali benar-benar diperlukan.
- Jangan mengubah fitur existing yang sudah berjalan.
- Jangan mengubah routing existing.
- Jangan mengubah autentikasi existing.
- Jangan mengubah logic pemeriksaan kesehatan.
- Jangan mengubah role permission yang sudah ada.
- Jangan menghapus fitur apa pun.
- Fokus hanya pada UX untuk proses INVITE VIA EMAIL dan DELETE ACCOUNT.
- Pertahankan design system, typography, spacing, icon style, dan color grading website yang sekarang.
- Semua perubahan harus responsive untuk mobile, tablet, dan desktop.
- Pastikan tidak menyebabkan regresi pada halaman lain.

==================================================
1. FITUR INVITE USER VIA EMAIL
==================================================

Saat Admin mengundang user melalui email, sekarang jangan hanya menampilkan:

" Mengirim... "

Saya ingin proses pengiriman terlihat seperti proses yang benar-benar sedang berlangsung.

Form existing:

- Nama lengkap
- Email Google target
- Role / Tier
- Tombol "Kirim undangan"

Pertahankan form tersebut.

Tambahkan UX loading yang lebih profesional.

--------------------------------------------------
1.1 BUTTON STATE
--------------------------------------------------

Saat tombol:

"Kirim undangan"

ditekan:

ubah menjadi:

"Menyiapkan undangan..."

dengan loading spinner.

Button harus disabled selama proses berjalan.

Prevent double submit.

User tidak boleh bisa menekan tombol berkali-kali.

--------------------------------------------------
1.2 FULL PROCESS LOADING MODAL
--------------------------------------------------

Setelah submit berhasil dikirim ke backend, tampilkan modal/dialog proses pengiriman.

Contoh:

--------------------------------
        ✉
   Mengirim undangan

Mohon tunggu, undangan sedang
dikirim ke email tujuan.

   ● ─── ○ ─── ○ ─── ○

Menyiapkan
undangan

Mengirim
email

Menunggu
konfirmasi

Selesai
--------------------------------

Gunakan animasi yang smooth.

Tidak perlu animasi berlebihan.

Gunakan:
- fade
- scale
- progress animation
- spinner
- icon transition

Durasi animasi harus terasa cepat dan profesional.

JANGAN membuat loading palsu terlalu lama.

Status harus mengikuti kondisi request/API sebenarnya.

--------------------------------------------------
1.3 STEP PROGRESS
--------------------------------------------------

Gunakan 4 tahap:

STEP 1
"Menyiapkan undangan"

STEP 2
"Mengirim email"

STEP 3
"Email berhasil dikirim"

STEP 4
"Selesai"

Step yang aktif mempunyai:
- animated indicator
- spinner atau pulse

Step yang selesai:
- check icon
- transition halus

Step yang belum:
- icon abu-abu

--------------------------------------------------
1.4 SUCCESS STATE
--------------------------------------------------

Jika API berhasil:

Tampilkan success state:

✓

"Undangan berhasil dikirim!"

"Undangan telah dikirim ke:
[email user]"

Tambahkan informasi:

"User dapat mengikuti tautan pada email
untuk bergabung ke Desa Sehat Kenanga."

Button:

" Selesai "

Setelah klik:
- tutup modal
- reset form jika memang behavior existing seperti itu
- refresh daftar user jika diperlukan
- tampilkan toast success

Contoh toast:

"Undangan berhasil dikirim ke email tujuan."

--------------------------------------------------
1.5 ERROR STATE
--------------------------------------------------

Jika API gagal:

Tampilkan:

✕

"Gagal mengirim undangan"

"Undangan tidak dapat dikirim saat ini."

Tampilkan alasan error jika backend memberikan error yang aman ditampilkan.

Contoh:

"Terjadi masalah pada layanan email."

Button:

"Coba lagi"

dan

"Tutup"

Jika klik "Coba lagi":
- ulangi request
- tampilkan loading kembali

Jangan reload halaman.

--------------------------------------------------
1.6 EMAIL SUDAH TERDAFTAR
--------------------------------------------------

Jika backend mengembalikan kondisi email sudah terdaftar:

Tampilkan state khusus:

⚠

"Email sudah terdaftar"

"Email tersebut sudah memiliki akun
di Desa Sehat Kenanga."

Berikan opsi:

"Tutup"

Jangan menganggap kondisi ini sebagai server error.

--------------------------------------------------
1.7 ROLE / TIER VALIDATION
--------------------------------------------------

Sistem memiliki 5 Tier/Role.

Tetap pertahankan role system existing.

Untuk fitur:

"Undang pengguna via email"

hanya boleh tersedia untuk:

Tier 1
Tier 2
Tier 3

Tier 4 dan Tier 5 TIDAK boleh diundang menggunakan fitur email ini.

Jika user memilih Tier 4 atau Tier 5:

- tampilkan warning
- disable tombol submit

Contoh:

"Undangan via email hanya tersedia untuk Tier 1–3."

Jangan hanya mengandalkan frontend.

Backend juga wajib melakukan validation.

Frontend dan backend harus konsisten.

==================================================
2. DELETE ACCOUNT UX
==================================================

Sekarang fitur hapus akun juga ingin dibuat lebih profesional.

Jangan langsung:

"Hapus → akun hilang → toast"

Saya ingin ada confirmation + proses loading + success/error state.

==================================================
2.1 DELETE CONFIRMATION MODAL
==================================================

Ketika Admin menekan:

"Hapus akun"

tampilkan confirmation modal.

Contoh:

--------------------------------
        🗑

      Hapus Akun?

Apakah Anda yakin ingin menghapus
akun ini?

Tindakan ini dapat menghapus data
terkait akun secara permanen dan
tidak dapat dibatalkan.

Ketik "HAPUS" untuk melanjutkan.

[________________]

[Batal]       [Hapus Akun]
--------------------------------

Tombol "Hapus Akun" harus disabled
sebelum user mengetik:

HAPUS

Case-insensitive boleh digunakan.

Contoh:
hapus
HAPUS
Hapus

boleh dianggap valid.

--------------------------------------------------
2.2 VISUAL WARNING
--------------------------------------------------

Gunakan warna warning/error secukupnya.

Jangan membuat seluruh halaman merah.

Gunakan:
- icon trash
- border ringan
- warning box
- tombol destructive

Design tetap mengikuti color system website.

==================================================
2.3 DELETE PROCESS LOADING
==================================================

Setelah user melakukan konfirmasi:

Tampilkan modal progress.

Contoh:

--------------------------------
        🗑
     Menghapus akun

Mohon tunggu, akun sedang diproses.

✓ Memeriksa data

● Menghapus akun

○ Membersihkan data terkait

○ Selesai

--------------------------------

Gunakan progress animation yang smooth.

Tahapan:

1. "Memeriksa data"
2. "Menghapus akun"
3. "Membersihkan data terkait"
4. "Selesai"

Status harus mencerminkan proses aktual sebanyak mungkin.

Jangan membuat progress palsu yang menunggu terlalu lama.

==================================================
2.4 DELETE SUCCESS
==================================================

Jika berhasil:

Tampilkan:

✓

"Akun berhasil dihapus"

"Data akun dan data terkait telah
dihapus dari sistem."

Button:

"Kembali ke dashboard"

atau

"Selesai"

Jika behavior existing membutuhkan redirect:

gunakan redirect yang sudah ada.

Jangan membuat routing baru jika tidak diperlukan.

==================================================
2.5 DELETE ERROR
==================================================

Jika gagal:

✕

"Gagal menghapus akun"

"Terjadi masalah saat menghapus akun."

Button:

"Coba lagi"

dan

"Tutup"

Jangan reload halaman.

Jangan menghapus data dari UI jika backend sebenarnya gagal.

UI harus mengikuti response backend.

3. TOAST NOTIFICATION
==================================================

Gunakan toast notification yang konsisten.

SUCCESS:

✓
"Undangan berhasil dikirim."

ERROR:

✕
"Gagal mengirim undangan."

WARNING:

⚠
"Email sudah terdaftar."

DELETE SUCCESS:

✓
"Akun berhasil dihapus."

DELETE ERROR:

✕
"Gagal menghapus akun."

Toast:
- muncul dengan slide/fade
- memiliki duration yang wajar
- bisa ditutup manual
- tidak menutupi tombol penting
- responsive mobile

4. ANIMATION SYSTEM
==================================================

Gunakan animasi yang subtle dan profesional.

Prioritas:

- opacity
- translate
- scale
- spinner
- progress
- icon morph/check
- skeleton jika memang diperlukan

Hindari:

- efek flashy
- confetti berlebihan

Website adalah portal administrasi kesehatan desa.

Feel yang diinginkan:

"modern"
"professional"
"trusted"
"clean"
"friendly"

Bukan seperti aplikasi gaming.

==================================================
5. RESPONSIVE
==================================================

Semua modal harus responsive.

Desktop:

Modal sekitar 420–520px.

Mobile:

Modal hampir full width dengan margin aman.

Pastikan:
- tidak overflow horizontal
- tombol tidak keluar layar
- text tidak terpotong
- progress step dapat berubah menjadi vertical jika layar kecil
- toast tidak menutupi bottom navigation
- input "HAPUS" mudah digunakan di mobile

==================================================
6. ACCESSIBILITY
==================================================

Pastikan:

- modal menggunakan proper dialog semantics
- keyboard navigation
- ESC dapat menutup modal jika kondisi memungkinkan
- focus management
- button disabled state jelas
- loading state tidak dapat di-submit dua kali
- aria-label pada icon-only button
- contrast tetap bagus pada light dan dark mode

==================================================
7. DARK MODE + LIGHT MODE
==================================================

Pertahankan light mode dan dark mode existing.

Pastikan:

Light:
- background tetap bersih
- card putih
- border subtle
- teal sebagai primary
- destructive menggunakan warna merah secara proporsional

Dark:
- jangan menggunakan pure black jika design system existing tidak menggunakannya
- gunakan surface dark existing
- border tetap terlihat
- text memiliki contrast yang baik
- modal tetap terlihat jelas

Jangan membuat dark mode dan light mode terasa seperti dua aplikasi berbeda.

==================================================
8. BACKEND SAFETY
==================================================

Jangan hanya memperbaiki frontend.

Untuk INVITE:
- validasi role/tier di backend
- validasi email
- prevent duplicate invite jika diperlukan
- handle email service error
- return response yang jelas

Untuk DELETE:
- authorization wajib dilakukan backend
- user tidak boleh menghapus akun yang bukan kewenangannya
- pastikan permission role tetap berjalan
- jangan melakukan delete jika authorization gagal
- return error response yang jelas

Jangan expose:
- API key
- secret
- token
- credential
- internal error detail
